# 领域说明

## 1. 业务背景

本服务面向晶圆制造产线的制程批次管理与配方版本隔离场景，核心目标是：

- 批次在任何站点加工时，其所用的**工艺路线修订、站点顺序、配方快照、量测计划**必须与其首次进站时刻冻结的版本严格一致，不受后续主数据升级影响；
- 设备与腔体必须具备匹配站点的能力，且其**资质窗口必须完整覆盖运行区间**；
- 量测异常触发暂扣，暂扣未关闭前阻断批次及其全部子批的后续站点操作；
- 返工必须生成**新的路线修订**并从指定站点重入，旧运行、旧量测、旧暂扣、旧快照一律不可改写；
- 全链路保留谱系（批次父子关系、晶圆迁移记录）与结构化审计，历史不可逆。

## 2. 领域对象

| 对象 | 说明 | 关键不变量 |
| --- | --- | --- |
| 产品族 ProductFamily | 晶圆批次归属的产品分类 | 编码唯一 |
| 站点 Station | 工序站点，声明要求的能力标签 | 编码唯一 |
| 工艺路线 Route | 属于产品族的路线，拥有多个修订 | 编码唯一 |
| 路线修订 RouteRevision | 版本化的站点序列；DRAFT→ACTIVE→RETIRED | 同路线修订号唯一；启用后站点序列不可改 |
| 配方 Recipe | 按设备族适配的工艺配方 | 编码唯一；只能在适配设备族执行 |
| 配方版本 RecipeVersion | 版本化配方；启用时生成**不可变快照** | 同配方版本号唯一；快照生成后不可改 |
| 设备 Equipment | 挂在站点下、属于设备族的加工设备 | 编码唯一 |
| 腔体 Chamber | 设备的加工腔体，携带能力标签 | 同设备编码唯一；能力须覆盖站点要求 |
| 资质窗口 Qualification | 设备（或腔体）在站点上的有效资质区间 | valid_to 必须晚于 valid_from |
| 量测计划 MetrologyPlan | 抽样槽位、最小样本数、判定阈值 | 同编码版本号唯一 |
| 批次 Lot | 在制批次，支持父子批谱系 | 编码唯一；首次进站冻结路线 |
| 晶圆 Wafer | 单片晶圆，批内槽位唯一 | 同一晶圆不得同时处于两个运行 |
| 迁移记录 WaferMove | 晶圆批次间迁移的不可变记录 | 只增不改 |
| 制程运行 Run | 批次在某站点某腔体的一次加工 | 附着冻结修订与配方快照 |
| 读数 Reading | 晶圆位置量测值；迟到量测标记 late | 封存后不可改；late 不参与判定 |
| 暂扣 Hold | 阻断批次的异常处置单 | OPEN 才阻断；复判只一次 |
| 返工记录 ReworkRecord | 关联暂扣与新修订的返工凭证 | 只增不改 |
| 放行记录 Release | 站点间放行与关闭的凭证 | 只增不改 |
| 审计事件 AuditEvent | 结构化审计，随业务事务提交/回滚 | 只增不改 |
| 作业 Job | 持久化后台作业 | 支持失败重试与重启恢复 |

## 3. 核心业务规则

1. **首次进站冻结**：批次第一次进站时，将当前启用的路线修订、站点顺序、每站配方启用版本的不可变快照、量测计划快照整体固化到批次上（freeze snapshot）。之后该批次所有运行只引用快照。
2. **设备与配方资格校核**：开工时校验——设备挂在该站点、设备 ACTIVE、腔体 ACTIVE 且能力标签覆盖站点要求、配方设备族与设备族一致、存在覆盖开工时刻的活跃资质窗口；完工时复核资质窗口覆盖完整运行区间，未覆盖则标记 `qual_covered=false`，进入“过期资质未复判”查询。
3. **站点顺序**：进站/放行只允许严格按冻结快照的 seq 递增，任何越站被拒绝。
4. **晶圆唯一运行**：同一晶圆不得同时处于两个 RUNNING 运行。
5. **量测时序**：运行完工后才能提交量测；封存时校验抽样覆盖计划槽位与最小数量；判定后补录的读数标记 late，附着原运行但不覆盖当前有效判定。
6. **暂扣阻断**：任何未关闭暂扣阻断该批次、其全部祖先与全部后代批次的进站、开工、放行。
7. **复判**：RELEASE 恢复原路线继续；REWORK 创建新路线修订并从指定站点重入（重入站点不得超过当前站点），批次冻结快照重建（配方取当前启用版本，即“换版”），旧记录不可改写；SCRAP 报废批次。
8. **幂等**：所有写操作接受业务幂等键（请求头 `Idempotency-Key` 或 `idempotency_key` 字段），重复请求返回首次结果（响应头 `Idempotent-Replay: true`）。
9. **乐观锁**：批次、修订、配方版本、设备、量测计划、运行、暂扣均携带版本号，状态更新必须匹配期望版本。
10. **事务完整性**：拆分与晶圆迁移、进站与运行创建、完工与站点推进、量测封存与暂扣生成、复判关闭与返工换版均在单一 SQLite 事务内完成，任一步失败整体回滚且不残留审计。

## 4. 分层

```
cmd/server            服务入口（PORT、DB_PATH、优雅关闭）
internal/config       环境配置
internal/clock        可注入时钟（Real / Manual）
internal/logx         结构化日志（slog JSON）
internal/domain       领域模型、枚举、状态转换表、分页、错误
internal/rules        版本与资格纯规则（冻结、资质、兼容、抽样、判定、阻断、返工）
internal/repository   Repository 接口与查询视图
internal/sqlite       SQLite 实现（迁移、事务、乐观锁、游标分页）
internal/service      服务编排（业务事务、幂等、审计）
internal/httpx        HTTP 层（路由、处理器、统一错误、中间件）
internal/jobs         后台作业（调度、资质扫描、超时检查、暂扣升级、重试）
```
